ML pipeline walkthrough

Do clinical models trained before 2020 still work after it?

Seven relational EHR tables become one patient-level feature matrix. Three classifiers are trained on patients first seen before 2020 and tested on patients first seen after, a real temporal distribution shift. Continual learning then measures how much of the lost performance an update recovers.

Data to decision

From raw tables to a feature matrix

01Loadpatients, encounters, conditions, medications, procedures, immunizations, observations
02Label1 if ever diagnosed with the chosen condition (top-15 list)
03AggregatePer-patient counts, cost mean/std, vitals and labs mean/std
04SplitFirst encounter before 2020 → D1; 2020 or later → D2
05TrainDecision Tree, RBF SVM, MLP on D1
06Stress-testD1 models on the held-out D2 test set
07UpdateWarm-start or retrain, then re-measure on D2
Why 2020

A distribution shift that actually happened

A random train/test split assumes the future looks like the past. Here the split is by the year of each patient's first encounter, and the cutoff is the COVID-19 onset, when healthcare utilisation measurably changed. The Preprocessing tab puts D1 and D2 descriptive statistics side by side, so the drift is visible before any model is trained.

D1, historical

First encounter before 2020. Training and in-distribution test set.

D2, current

First encounter in 2020 or later. Temporal-shift test set and continual-learning data.

Three model families

Models and how each one is updated

ModelConfigurationContinual-learning update
Decision Treemax_depth=10, min_samples_split=10Retrain on D1 + D2
SVM (RBF)C=1.0, gamma='scale', scaled inputsRetrain on D1 + D2
MLP(100, 50), early stopping, scaled inputsDeep-copy, then fine-tune on D2 with warm_start=True

Evaluation covers accuracy, precision, recall, F1, confusion matrices and ROC curves. Complexity sweeps cover tree depth, SVM C and the MLP loss curve, and interpretability uses Gini importance plus permutation importance on the same held-out test set.

Being honest about the label

Leakage controls

Financial outcome excluded

HEALTHCARE_EXPENSES is never a feature.

Target removed from comorbidities

CONDITION_COUNT excludes the target diagnosis. Counted naively, every positive patient has a count of at least 1, so the feature encodes the label.

Known limitation. Medication, procedure and observation aggregates cover the whole record, so for positive patients they include events after diagnosis. Cutting each history at the diagnosis date is the next fix.
